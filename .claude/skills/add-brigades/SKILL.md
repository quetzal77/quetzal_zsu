# Додавання бригад з `docs/brigades.md` у БД

Ти виконуєш ту саму роботу, яку раніше робили вручну для розділу «Десантно-штурмові війська»:
читаєш один розділ таблиці з `docs/brigades.md`, зіставляєш колонки зі схемою `data/schema.sql`
і вставляєш дані в `data/quetzal_zsu.db` через Python (`sqlite3`, stdlib — CLI `sqlite3` у цьому
середовищі відсутній).

Аргумент скіла (`$ARGUMENTS`) — назва розділу (заголовок `##` у brigades.md), напр. «ССО»,
«Корпус морської піхоти ВМС», «Артилерія». Якщо аргумент не передано — запитай користувача,
який розділ обробити, або запропонуй перший ще не імпортований.

## Крок 0 — контекст перед вставкою

1. Прочитай `data/schema.sql`, щоб пам'ятати актуальні колонки/constraints (`brigades`,
   `locations`, `battles`, junction-таблиці). Якщо схема відрізняється від описаної нижче —
   довіряй файлу, а не цій інструкції.
2. Витягни поточний вміст lookup-таблиць одним python-скриптом (encoding! на Windows PowerShell/
   Bash з кирилицею завжди виставляй `PYTHONIOENCODING=utf-8` і перенаправляй у файл, інакше
   `UnicodeEncodeError` на cp1252):
   ```
   PYTHONIOENCODING=utf-8 python3 -c "..." > /tmp/lookup_dump.txt; cat /tmp/lookup_dump.txt
   ```
   Потрібні: `military_branches`, `army_corps`, `troop_types`, `regions`, `locations`.
3. Витягни список уже існуючих `brigades.name`, щоб не вставити дублікат при повторному запуску
   скіла (ідемпотентність — якщо назва бригади вже є в таблиці, пропусти її й повідом користувача).

## Крок 1 — розпарси розділ brigades.md

Кожен розділ — markdown-таблиця з колонками, які **відрізняються між розділами**:

| Тип розділу | Колонка 2 | Колонка 7 |
|---|---|---|
| Десантно-штурмові, піхота, танкові, ССО, артилерія тощо | `Корпус` (напр. «7 АК») | `Де почали війну` |
| Територіальна оборона | `Оперативне угруповання` (напр. «РУ "Захід"») | `Де почали війну` |
| ДПС | `Прикордонний загін` (текстова назва, не АК) | `Де почали війну` |
| Авіаційні розділи (Бойова/Транспортна авіація, ЗРВ) | `Корпус` (зазвичай `—`) | `Техніка` — озброєння, не бойовий шлях |

Для кожного рядка таблиці визнач:

- **`name`** — прибери провідний рік-префікс у дужках, напр. `(2022) 46-та ...` → `46-та ...`.
  Рік заснування вже піде в `formed_date`, дублювати в назві не треба.
- **`corps_id`** — якщо в колонці «Корпус» число + «АК» (напр. «16 АК»), знайди відповідний
  `army_corps.corps_name`, що містить це число (напр. «16-й армійський корпус»). Якщо там
  назва зброї/техніки (напр. «БМ-30 "Смерч"», «M142 HIMARS») або ОК/угруповання чи текстова
  прикордонна назва — **не намагайся підставити corps_id силоміць**: залиш `NULL` і перенеси
  сирий текст у `description`.
- **`troop_type_id`** — визнач за родом військ із назви бригади/полку та заголовка розділу
  (ключові слова): десантна/аеромобільна/десантно-штурмова/єгерська → «Десантна»; механізована/
  мотопіхотна → «Механізована»; танкова/важка механізована → «Танкова» (якщо є явна «Танкова»)
  чи «Механізована» (якщо важка механізована ближче до піхоти — вирішуй за контекстом розділу,
  за потреби запитай користувача); штурмова → «Штурмова»; артилерійська/реактивна/ракетна
  (польова) → «Артилерійська»; ППО/зенітна ракетна → «ППО»; морська піхота/берегова оборона →
  «Морська піхота»; армійська авіація (вертольоти) → «Армійська авіація»; безпілотні системи →
  «БпЛА». Якщо жодна категорія не підходить (напр. ССО, інженерні війська, прикордонники,
  Нацгвардія) — **зупинись і запитай користувача**, чи додати нову lookup-категорію в
  `troop_types`, а не вигадуй притягнуту відповідність.
- **`military_branch_id`** — за заголовком розділу:
  - Десантно-штурмові війська → «Десантно-штурмові війська»
  - ССО → «Сили спеціальних операцій»
  - Корпус морської піхоти ВМС → «Військово-морські сили»
  - Сили безпілотних систем → «Сили безпілотних систем»
  - Танкові та важкі механізовані, Штурмові полки, Гірські та єгерські, Піхота, Артилерія,
    Армійська авіація, ППО сухопутних військ, Інженерні війська → «Сухопутні війська»
  - Територіальна оборона → «Сили територіальної оборони»
  - Бойова авіація, Транспортна авіація, Зенітні ракетні війська (Повітряні сили) →
    «Повітряні сили»
  - Державна прикордонна служба (ДПС), МВС / Національна гвардія → **немає відповідного рядка
    в `military_branches`**. Не вигадуй наближення — спитай користувача, чи створити нові
    lookup-значення («Державна прикордонна служба», «Національна гвардія») перед вставкою бригад
    цих розділів.
- **`location_id`** — розпарси «ППД»:
  - формат «м. Х, Y область» → `city_name='Х'`, знайди `region_id` по назві області (без слова
    «область»/«район», напр. «Дніпропетровська область» → регіон «Дніпропетровська»).
  - формат без міста, лише «Y область» → `city_name='Y область'` (та ж область як region_id) —
    зберігаємо як є, щоб не втрачати інформацію і не вигадувати неіснуюче місто.
  - кілька міст в одній клітинці (напр. «м. Костянтинівка, м. Дружківка») → візьми перше як
    `location_id`, решту допиши в `description` («ППД також м. …»).
  - `—`, `.` або порожньо → `location_id = NULL`.
  - Перед вставкою нової локації перевір, чи вона вже є в `locations` (унікальність
    `(city_name, region_id)`) — не створюй дублікат, використай існуючий `location_id`.
  - Якщо область не вдається зіставити з жодним рядком `regions` (АР Крим/Севастополь вже є в
    довіднику — перевір перед тим, як вважати регіон відсутнім) — запитай користувача.
- **`formed_date` / `flag_date`** — конвертуй у ISO (`YYYY-MM-DD`) **лише** коли в джерелі є повна
  дата (день+місяць+рік або `DD.MM.YYYY`). Якщо є лише рік, сезон («весна 2022»), кілька дат через
  «/», чи префікс `>` («після дати», флаг невідомий точно) — залиш поле `NULL` і перенеси сирий
  текст у `description` (напр. «Засновано: весна 2022.», «Прапор: після 28 червня 2022.»).
  Не підставляй вигадані дні на власний розсуд.
  Пам'ятай про `CHECK (formed_date IS NULL OR flag_date IS NULL OR formed_date <= flag_date)` —
  якщо обидві дати точні, переконайся, що порядок логічний; якщо ні — зверни увагу користувача.
- **`description`** — зібери туди все, що не має власної колонки: «Походження», «Де почали
  війну»/«Техніка», нотатки про приблизні дати, додаткові ППД. Формат: короткі речення
  `Ключ: значення.`, розділені крапкою з пробілом, без markdown-розмітки.
- **`emblem_file`** — завжди `NULL` (фото не імпортуються цим скілом, це окрема задача).

## Крок 2 — виконай вставку

Пиши один self-contained python-скрипт на розділ (через `Bash`, heredoc), який:

1. `PRAGMA foreign_keys = ON`.
2. Спершу вставляє нові `locations` (якщо потрібні), запам'ятовуючи `lastrowid` у словник
   `city_name -> location_id` для використання нижче — **не хардкодь ID вручну**, бо вони
   залежать від того, що вже є в базі.
3. Для кожної бригади розділу — `INSERT INTO brigades (...)`, пропускаючи ті, чиє `name` вже є
   в базі (SELECT перед INSERT або `WHERE NOT EXISTS`).
4. У кінці — `PRAGMA foreign_key_check` і друк списку помилок (має бути порожній).
5. Друк підсумку: скільки бригад вставлено, скільки пропущено як дублікати, скільки локацій
   створено.

Обгортай усю вставку однієї транзакції (`sqlite3` за замовчуванням у autocommit-режимі з
явним `commit()` в кінці — якщо десь падає виняток до `commit()`, зміни не застосуються, це ок).

## Крок 3 — перевір і відзвітуй

Виконай SELECT з JOIN на `army_corps`/`troop_types`/`locations` для щойно вставлених
`brigade_id`, покажи користувачу компактну таблицю для перевірки (як у попередньому імпорті
ДШВ). Явно скажи, які рядки довелось лишити з `NULL` corps/location/датами через неповні дані
в джерелі, і які припущення (нова lookup-категорія, вибір першого міста з кількох) ти зробив.

## Що НЕ робити

- Не змінюй уже вставлені раніше бригади (інші розділи) без окремого прохання.
- Не додавай новий рядок у `military_branches`/`army_corps`/`troop_types`/`regions` без
  підтвердження користувача — це довідники, які впливають на всю базу.
- Не округляй/вигадуй точні дати, коли джерело дає лише рік або сезон.
- Не імпортуй фото/traditions/equipment цим скілом — вони не описані в `brigades.md`.
